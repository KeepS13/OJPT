# 分页功能测试说明

## 前置条件

1. **后端服务**：OJPT 后端已启动，且列表接口已改为分页（返回 `{ records, total, current, size, pages }`）。
2. **前端**：在项目根目录执行 `npm run dev`，浏览器访问控制台显示的地址（一般为 http://localhost:5173）。
3. **API 地址**：前端默认请求 `http://localhost/api`，若后端不是该地址，请修改 `src/api/request.ts` 的 `baseURL` 或配置代理。

---

## 一、校方账号（SchoolView）

1. 使用**校方角色**登录。
2. 进入「校方管理」页（或学校管理相关入口）。
3. 依次切换 Tab：**院系管理**、**班级管理**、**教师管理**、**学员管理**。
4. **预期**：
   - 每个 Tab 下表格下方都有分页条（显示“共 x 条”、每页条数 10/20/50/100、上一页/页码/下一页、跳转）。
   - 切换页码或修改每页条数后，表格数据会重新请求并刷新。
   - 打开浏览器开发者工具 → Network，筛选 XHR/Fetch，查看请求 URL 是否带 `page`、`size` 参数（如 `?page=1&size=10`），响应 body 中 `data` 是否为 `{ records: [...], total, current, size, pages }`。

---

## 二、教师账号（TeacherView）

1. 使用**教师角色**登录。
2. 进入「教师后台」。
3. **班级管理 Tab**：
   - 表格下方应有分页条，翻页/改每页条数后列表会刷新。
4. 点击某一班级的 **学员管理**：
   - 切换到「学员管理」Tab，表格下方应有分页条，请求带 `page`、`size`。
5. 点击同一班级的 **申请审核**：
   - 切换到「申请审核」Tab，同样应有分页条。
6. 点击同一班级的 **教师管理**：
   - 切换到「教师管理」Tab，同样应有分页条。
7. **预期**：上述 4 个列表的请求 URL 均带 `page`、`size`，响应为分页结构。

---

## 三、学员账号（StudentView）

1. 使用**学员/学生角色**登录。
2. 进入「学员中心」。
3. **我的班级**：
   - 表格下方应有分页条，翻页或改每页条数后列表刷新，请求带 `page`、`size`。
4. 对某个已加入的班级点击 **查看成员**：
   - 弹窗内成员表格下方应有分页条，请求为分页接口（带 `page`、`size`）。

---

## 四、管理员（AdminView，已有分页）

1. 使用**管理员**登录。
2. 进入用户管理、学校列表等列表页。
3. **预期**：列表为分页加载，请求带 `page`、`size`，响应为 `records` + `total`，与之前行为一致。

---

## 六、接口层验证（可选）

若只想确认请求/响应格式，可在控制台 Network 中：

- 筛选列表相关请求（如 `/school/departments`、`/teacher/classes`、`/student/classes` 等）。
- 查看 **Request URL**：应包含 `page`、`size`（如 `page=1&size=10`）。
- 查看 **Response**：`data` 应为 `{ records: Array, total: number, current: number, size: number, pages: number }`，表格展示的是 `records`。

---

## 若后端未就绪

若后端仍返回**全量数组**（无 `records`/`total`），前端已做兼容：会把整段数组当作当前页、`total` 为数组长度，分页条可能只显示一页，但不会报错。待后端改为分页后，无需改前端即可正常分页。
