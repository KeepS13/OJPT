# 3系统需求分析

## 3.1可行性分析

### 3.1.1技术可行性

系统采用前后端分离架构。后端使用SpringBoot、Spring Security、MyBatis-Plus、MySQL、Redis、Flyway和Docker，前端使用Vue 3、TypeScript、Element Plus、Pinia和Axios。这些技术在Web应用和在线判题类系统中使用较广，文档和社区资料较丰富，能够满足毕业设计开发和演示需要。

判题功能通过Docker执行用户代码，能够避免业务服务直接运行用户程序。虽然当前系统不是大规模竞赛平台，但Docker已经能够支撑C/C++、Java、Python3等语言的基本运行和结果收集，因此在技术上可行。

### 3.1.2经济可行性

系统开发所需软件均可使用开源或免费版本，包括JDK、Node.js、MySQL、Redis、Docker、SpringBoot、Vue 3、Element Plus、Vitest和Playwright等。项目本地开发和测试可以在普通开发电脑上完成，不需要额外购买专用设备或商业软件，因此具备经济可行性。

### 3.1.3操作可行性

系统面向两类用户。普通用户通过浏览器访问首页、题库、做题页和个人中心，操作方式符合常见Web应用习惯；管理员通过后台菜单进入用户管理、题目管理、标签管理和统计概览页面，使用表格、筛选、表单和弹窗完成维护操作。系统交互路径清晰，具备操作可行性。

### 3.1.4运行可行性

系统依赖前端Vite服务、后端SpringBoot服务、MySQL、Redis和Docker。功能说明书中已经整理了本地运行截图，包括前端启动、后端启动、数据库端口、Redis端口、Docker版本、判题镜像和Docker Compose状态等。现有材料能够支撑论文运行环境说明和测试验证。

## 3.2用户角色分析

OJPT当前主线角色分为普通用户和管理员。匿名访问者可以浏览公开题库和已发布题目，但无法保存代码草稿、运行代码、正式提交和查看个人训练数据。

表3-1用户角色说明

| 角色 | 权限范围 | 主要目标 |
| --- | --- | --- |
| 匿名访问者 | 浏览首页、题库列表和已发布题目详情 | 了解平台题目内容 |
| 普通用户 | 登录、做题、运行代码、提交代码、查看训练数据、维护个人资料 | 完成个人编程训练 |
| 管理员 | 具备普通用户能力，并可进入后台管理用户、题目、测试用例、标签、统计和判题环境 | 维护平台基础数据和运行环境 |

普通用户的核心需求是快速找到题目、阅读题面、编辑代码、运行样例、正式提交并查看结果。管理员的核心需求是维护训练内容和用户状态，保证题目、测试用例和标签数据准确可用。

## 3.3功能需求分析

### 3.3.1认证与账号功能

认证与账号功能包括登录、注册、刷新令牌、当前用户信息查询、退出登录和密码重置申请。用户可以使用用户名、手机号或邮箱进行登录；注册成功后系统返回登录态；用户退出登录后访问令牌会失效；忘记密码时可以提交密码重置申请，由管理员进行审核。

认证功能需要满足以下要求。

1. 登录成功后返回访问令牌、刷新令牌和用户身份信息。
2. 登录失败时返回清晰错误信息。
3. 禁用或待审核用户不能正常进入系统。
4. 访问需要登录的页面时，前端应根据令牌状态进行拦截或尝试恢复会话。
5. 管理员可以审核密码重置申请。

### 3.3.2普通用户功能

普通用户功能包括首页入口、题库浏览、题库筛选、题目详情、个人资料、账号安全、训练看板和提交记录。

题库列表需要支持关键词、题号、难度、标签、完成状态和分页查询。题目详情需要展示题号、标题、难度、时间限制、内存限制、Markdown题面和公开样例。个人中心需要支持资料查看与修改、头像上传与删除、用户名、邮箱、手机号和密码修改，以及账号注销。训练看板需要展示提交次数、通过数量、难度分布、状态分布和近期提交记录。提交记录页面需要支持分页查看提交状态、语言、题目、耗时、内存和源码。

### 3.3.3做题与判题功能

做题与判题功能是系统核心。用户进入做题页后，系统加载题目详情、公开样例、代码草稿和默认代码模板。用户可以选择语言、编辑代码、使用样例或自定义测试用例运行代码，也可以正式提交代码进行判题。

该模块需要满足以下要求。

1. 支持C/C++、Java、Python3等语言。
2. 支持按题号加载题目和公开样例。
3. 支持按用户、题目和语言保存代码草稿。
4. 运行代码时返回每个测试用例的状态、输出、错误信息和耗时。
5. 正式提交时创建提交记录，并保存逐用例判题结果。
6. 隐藏用例结果对普通用户展示时需要隐藏敏感输入输出。
7. 判题完成后更新用户题目进度。

### 3.3.4管理员功能

管理员功能包括管理概览、判题环境健康检查、用户管理、密码重置审核、题目管理、测试用例维护和标签管理。

管理概览需要展示平台用户、题目、提交等统计信息。判题环境健康检查需要展示Docker可执行文件、Docker版本和语言镜像状态。用户管理需要支持用户列表、关键词搜索、状态筛选、角色筛选、详情查看、资料编辑、状态变更和删除。题目管理需要支持题目列表、草稿创建、题目编辑、发布、归档、测试用例维护、标签绑定和解绑。标签管理需要支持标签列表、新增、编辑和删除。

## 3.4非功能需求分析

### 3.4.1安全性需求

系统需要区分公开接口和敏感接口。题库列表和已发布题目详情可以匿名访问，代码草稿、运行代码、提交代码、个人中心和管理端接口必须登录后访问，管理端接口还必须具备管理员角色。Markdown渲染需要进行内容清洗，减少XSS风险。用户密码需要加密存储，令牌退出后需要进入黑名单或失效状态。

### 3.4.2可用性需求

系统页面应具有清晰导航和稳定布局。题库筛选条件应易于理解，做题页应提供代码编辑、测试用例和结果展示区域，个人中心和管理端长页面应保证可滚动。错误信息应以用户能够理解的方式展示，例如登录失败、权限不足、运行错误和编译错误。

### 3.4.3可靠性需求

系统应保证核心数据状态一致。题目发布后普通用户可见，归档后不应作为普通用户主列表内容展示；正式提交应保存提交记录和逐用例结果；判题完成后应更新用户题目进度；分页接口应返回正确的总数和页数。数据库迁移应通过Flyway保持表结构可复现。

### 3.4.4可维护性需求

系统应保持前后端职责清晰。后端接口按认证、用户、题库、判题和管理端划分，前端页面按普通用户和管理员功能划分。数据库表、接口路径、状态枚举和页面路由应在论文和功能说明书中保持一致，便于后续维护和答辩说明。
