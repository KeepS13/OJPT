# 论文格式与质量检查清单

本文档用于论文写作和定稿前自查。建议每完成一章后检查一次，最终 Word 排版完成后再整体检查一次。

## 1. 格式检查

- [ ] 使用 Microsoft Word 处理最终论文。
- [ ] A4 单面打印。
- [ ] 左侧装订。
- [ ] 页边距为上 25mm、下 20mm、左 30mm、右 30mm。
- [ ] 正文行距为固定值 23 磅。
- [ ] 字符间距为标准。
- [ ] 封面、原创性声明、目录不编页码。
- [ ] 目录后开始使用阿拉伯数字页码。
- [ ] 页码位于页面底部居中，五号 Times New Roman。
- [ ] 正文中文使用小四号宋体。
- [ ] 英文和数字按要求使用 Times New Roman。
- [ ] 一级标题小二号黑体，顶格。
- [ ] 二级标题四号黑体，顶格。
- [ ] 三级标题小四号黑体，顶格。
- [ ] 各级标题不放在页面最后一行。
- [ ] 每章按学院模板要求独立分页。
- [ ] 全文错别字和标点错误已检查。

## 1.1 分块字体检查

- [ ] 封面 `归 档 号` 为黑体小三。
- [ ] 封面主标题 `武汉工商学院毕业论文(设计)` 为宋体一号加粗居中。
- [ ] 封面学院、专业、年级、学生、学号、指导教师、职称、题目等字段为宋体小三加粗，英文和数字为 Times New Roman 小三加粗。
- [ ] 原创性声明标题为宋体二号加粗居中。
- [ ] 原创性声明正文为宋体四号，单倍行距，首行缩进 2 字符。
- [ ] 目录标题 `目 录` 为黑体小二居中。
- [ ] 目录中文条目为宋体小四。
- [ ] 目录英文条目、数字和页码为 Times New Roman 小四。
- [ ] 中文摘要标题 `摘  要` 为黑体小二居中。
- [ ] 中文摘要正文为宋体小四，英文和数字为 Times New Roman 小四。
- [ ] 中文 `关键词` 标签为黑体小四，关键词内容为宋体小四。
- [ ] 英文摘要标题 `Abstract` 为 Times New Roman 小二加粗居中。
- [ ] 英文摘要正文为 Times New Roman 小四。
- [ ] 英文 `Key words` 标签为 Times New Roman 小四加粗，内容为 Times New Roman 小四。
- [ ] 正文一级标题为黑体小二。
- [ ] 正文二级标题为黑体四号。
- [ ] 正文三级和四级标题为黑体小四。
- [ ] 正文段落中文为宋体小四，英文和数字为 Times New Roman 小四。
- [ ] 注释为中文宋体五号、英文和数字 Times New Roman 五号。
- [ ] 表题为黑体五号居中。
- [ ] 表内中文为宋体五号，英文和数字为 Times New Roman 五号。
- [ ] 图题为黑体五号居中。
- [ ] 图中说明文字为黑体五号。
- [ ] 代码英文和数字为 Times New Roman 五号，中文注释为宋体五号。
- [ ] 参考文献标题为黑体小二居中。
- [ ] 参考文献条目中文为宋体小四，英文和数字为 Times New Roman 小四。
- [ ] 附录标题为黑体四号顶格。
- [ ] 附录正文按正文规则设置。

## 2. 结构检查

- [ ] 封面字段完整。
- [ ] 原创性声明位于封面后、目录前。
- [ ] 目录独立成页。
- [ ] 目录包含摘要、Abstract、正文标题、参考文献、致谢。
- [ ] 中文摘要独立成页。
- [ ] 英文摘要独立成页。
- [ ] 关键词 3-5 个。
- [ ] 中英文关键词一一对应。
- [ ] 正文包含绪论、相关技术、需求分析、系统设计、系统实现、系统测试、结论。
- [ ] 参考文献位于正文后。
- [ ] 致谢位于参考文献后。
- [ ] 附录如有则另起一页。

## 3. 摘要检查

- [ ] 中文摘要说明研究背景或目的。
- [ ] 中文摘要说明系统主要内容。
- [ ] 中文摘要说明技术路线。
- [ ] 中文摘要说明实现结果或应用价值。
- [ ] 中文摘要不含图表。
- [ ] 中文摘要不含公式。
- [ ] 中文摘要不标引用编号。
- [ ] 英文摘要与中文摘要内容对应。
- [ ] 英文关键词与中文关键词顺序对应。

## 4. 正文专业性检查

- [ ] 论文主线明确为在线编程训练平台。
- [ ] 不把学校、班级、课程等历史模型写成当前主线功能。
- [ ] 每章开头有导入说明，不直接堆标题。
- [ ] 每章末尾有小结或自然收束。
- [ ] 技术介绍服务于系统实现，不写百科式堆砌。
- [ ] 需求分析区分用户需求、管理员需求和非功能需求。
- [ ] 系统设计覆盖架构、模块、数据库、接口、安全、判题环境。
- [ ] 系统实现按模块写清页面、接口和核心逻辑。
- [ ] 系统测试覆盖正常场景和异常场景。
- [ ] 结论总结已实现内容，不夸大未实现能力。
- [ ] 展望部分明确是后续方向。

## 5. 术语一致性检查

- [ ] 系统名称统一为 `OJPT 在线编程训练平台` 或 `在线编程训练平台`。
- [ ] `Spring Boot`、`Vue 3`、`MySQL`、`Redis`、`Docker`、`JWT` 写法统一。
- [ ] `题库`、`题目`、`测试用例`、`代码草稿`、`提交记录` 用词统一。
- [ ] `运行代码` 与 `正式提交` 区分清楚。
- [ ] `期望输出` 与 `实际输出` 区分清楚。
- [ ] `管理员` 与 `普通用户` 权限边界清楚。
- [ ] `判题`、`评测` 如混用，需要定义或统一。
- [ ] `Token`、`访问令牌`、`刷新令牌` 写法前后一致。

## 6. 图表检查

- [ ] 图表编号按章连续。
- [ ] 图题在图下方。
- [ ] 表题在表上方。
- [ ] 图题和表题均为黑体五号居中。
- [ ] 表格使用三线表。
- [ ] 表内中文为宋体五号。
- [ ] 表内数字和英文为 Times New Roman 五号。
- [ ] 图表在正文中有引用。
- [ ] 正文引用图表编号正确。
- [ ] 图和图题没有跨页分离。
- [ ] 表格没有跨页断裂或表头缺失。
- [ ] 页面截图清晰，关键信息可读。
- [ ] 设计图不是由截图替代。

## 7. 软件工程图检查

- [ ] 有系统功能模块图。
- [ ] 有系统顶层数据流图。
- [ ] 有系统零层数据流图。
- [ ] 有核心业务一层数据流图。
- [ ] 有系统总体架构图。
- [ ] 有核心实体属性图。
- [ ] 有数据库 E-R 图。
- [ ] 有用户登录系统流程图。
- [ ] 有题库筛选系统流程图。
- [ ] 有代码运行或提交异步判题系统流程图。
- [ ] 有管理员题目管理系统流程图。
- [ ] 图中实体、模块和数据流与真实项目一致。
- [ ] Docker 判题环境在架构或流程中体现。
- [ ] JWT 鉴权或角色权限在设计中体现。

## 8. 数据库与接口检查

- [ ] 数据库设计基于真实表结构。
- [ ] 核心表包含 `user`、`problem`、`tag`、`problem_tag`、`problem_test_case`。
- [ ] 做题与提交表包含 `problem_code_draft`、`submission`、`submission_case_result`、`user_problem_progress`。
- [ ] 数据库字段中文说明准确。
- [ ] 主键、外键或关联关系说明清楚。
- [ ] 接口清单来自真实后端接口。
- [ ] 接口路径、请求方法与实际一致。
- [ ] 认证接口、题库接口、运行提交接口、管理端接口均覆盖。
- [ ] 不写不存在的后端接口。

## 9. 测试检查

- [ ] 第 6 章有测试方法说明。
- [ ] 第 6 章有测试环境表。
- [ ] 功能测试覆盖登录、注册、题库、做题、运行、提交、个人中心、管理端。
- [ ] 异常测试覆盖错误密码、空输入、运行错误、未登录或权限不足。
- [ ] 接口测试覆盖主要 API。
- [ ] 前端测试覆盖题库筛选和做题页快捷键/测试用例逻辑。
- [ ] 后端测试覆盖认证、权限、题库、提交、判题环境。
- [ ] 测试表包含输入、步骤、期望结果、实际结果和结论。
- [ ] 测试结果不只写“通过”，有具体说明。
- [ ] 构建验证结果记录清楚。

## 10. 参考文献检查

- [ ] 参考文献标题为小二号黑体居中。
- [ ] 参考文献按 GB/T 7714-2015 编排。
- [ ] 文献序号为 `[1]`、`[2]` 格式。
- [ ] 正文引用编号与参考文献编号一致。
- [ ] 每条参考文献末尾有句号。
- [ ] 文献总数不少于 15 篇。
- [ ] 近 5 年文献不少于 80%。
- [ ] 英文文献不少于 3 篇。
- [ ] 不与开题报告参考文献重复。
- [ ] 不引用未实际阅读或无法核验的资料。
- [ ] Web 文献包含引用日期和 URL。

## 11. 项目一致性检查

- [ ] 论文描述与 `.docs/功能说明书` 一致。
- [ ] 论文描述与当前前端路由一致。
- [ ] 论文描述与当前后端 Controller 接口一致。
- [ ] 论文描述与当前数据库迁移和数据模型一致。
- [ ] 论文描述与当前测试用例一致。
- [ ] 页面截图来自当前系统。
- [ ] Swagger、Actuator、接口响应截图为最新可访问状态。
- [ ] 管理员功能只写用户、题库、题目、测试用例、标签、统计、判题环境。
- [ ] 普通用户功能只写首页、题库、做题、个人中心、训练看板、提交记录、账号安全。
- [ ] 不写未实现的课程、班级、教师批改或作业发布功能。

## 12. 文风检查

- [ ] 避免营销式表达，例如“极致体验”“行业领先”等。
- [ ] 避免空泛表达，例如“具有很高价值”但不说明原因。
- [ ] 避免口语化表达。
- [ ] 避免连续大段无引用背景描述。
- [ ] 避免 AI 式重复句型。
- [ ] 每个功能说明尽量包含输入、处理和输出。
- [ ] 每个设计说明尽量对应图表或代码实现。
- [ ] 每个测试说明尽量对应具体用例。
- [ ] 结论不夸大系统规模和实际应用范围。

## 13. 定稿前最终检查顺序

1. 按学校规范检查页面、字体、行距、页码。
2. 更新 Word 自动目录。
3. 检查所有图表编号和正文引用。
4. 检查所有参考文献和正文引用。
5. 检查摘要与结论是否对应。
6. 检查论文中所有功能是否确实已实现。
7. 检查截图是否为当前系统最新界面。
8. 检查错别字、标点、英文大小写和空格。
9. 导出 PDF 后再次检查分页、图表跨页和目录页码。
