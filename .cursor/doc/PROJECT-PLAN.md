## 1. 功能视角总览（领域 / 模块划分）

> 注：本节从业务视角拆分模块，每个模块下再细化到具体功能项，后续章节会给出表格化的状态跟踪。

- **1）用户与权限中心（当前重点）**
  - 账户注册 / 登录 / 登出
  - JWT 认证与续期
  - 多角色（学员、教师、校方、管理员）管理
  - 组织管理（学校 / 院系 / 班级）
  - RBAC 权限模型与菜单 / 接口授权
  - 用户资料与头像上传
  - 基础统计（用户数量、活跃度、按角色分布）

- **2）题库与题目管理（规划中）**
  - 题目 CRUD（单题增删改查）
  - 标签、难度、来源、知识点关联
  - 批量导入 / 导出（如 YAML / JSON / Excel）
  - 题解与讨论区

- **3）评测与提交系统（规划中）**
  - 多语言（C++ / Java / Python 等）代码提交
  - 沙箱判题（隔离运行 / 资源限制）
  - 判题结果（AC / WA / TLE / MLE 等）与运行详情
  - 重判与队列调度

- **4）训练 / 作业与竞赛模块（规划中）**
  - 训练计划与作业发布
  - 竞赛创建、报名与权限控制
  - 排行榜 / 封榜策略
  - 赛后统计与题目分析

- **5）学习分析与报表（规划中）**
  - 学员个人能力画像
  - 班级 / 学校维度统计
  - 题目通过率与难度分布分析

- **6）运维与系统管理**
  - 配置管理（系统参数、评测参数等）
  - 操作日志与审计（敏感操作记录）
  - 监控与告警（依赖 Actuator、日志采集等）

## 3. 前端调用与接口结构（可扩展规范）

本节重点说明：**前端如何调用后端接口，以及对应应如何编写测试**，为后续新增功能提供统一模板。

### 3.1 前端统一调用约定

- **统一请求封装**：前端通过 `OJPT-frontend` 中的 `src/api/request.ts` 封装 `axios`：
  - 统一处理 `baseURL`（开发环境通过 Vite 代理，生产环境通过 Nginx `/api`）。
  - 统一附加 JWT（`Authorization: Bearer <token>`）。
  - 统一处理错误提示、401/403 跳转、整数精度等。
- **全局状态**：
  - 认证信息与用户基本资料存放在 `pinia` 的 `auth` 相关 store（如 `src/stores/auth.ts`）。
  - 建议所有需要登录态的 API 调用都只从 store 读取 token，不从 `localStorage` 直接读取。
- **路由守卫**：
  - `vue-router` 使用 `meta.requiresAuth` 和 `meta.requiredRole` 控制访问。
  - 对应的接口权限由后端 Spring Security 6 + RBAC 决定。

### 3.2 前端调用 + 测试结构模板（示例）

> 下面以「用户登录」为示例，给出推荐的代码与测试结构，以便其他功能可以复用同一模式。

- **接口定义（示意）**
  - 后端接口：`POST /api/auth/login`
  - 请求：`{ username: string, password: string }`
  - 响应：`{ accessToken: string, refreshToken: string, user: { id: number, name: string, roles: string[] } }`

- **前端模块划分建议**
  - `src/api/auth.ts`
    - 导出 `login`, `logout`, `refreshToken` 等函数，仅做 HTTP 调用。
  - `src/stores/auth.ts`
    - 持久化 token 与 user 信息，对外暴露 `login`, `logout`, `isAuthenticated` 等方法。
  - `src/views/auth/LoginView.vue`
    - 仅关心表单与交互，调用 `authStore.login`。

- **前端测试结构建议**
  - 单元测试（使用 Vitest）：
    - `tests/unit/api/auth.spec.ts`：只测试 `src/api/auth.ts` 的 HTTP 调用是否正确处理正常/异常返回（通过 mock axios）。
    - `tests/unit/stores/auth.spec.ts`：测试登录成功/失败时 store 状态变化，token 是否正确写入/清除。
  - 组件测试：
    - `tests/components/LoginView.spec.ts`：挂载 `LoginView`，模拟用户输入和点击登录按钮，断言错误提示、跳转行为。
  - 端到端测试（可使用 Playwright 或 Cypress）：
    - `tests/e2e/auth-login.spec.ts`：在真实页面环境中验证从登录页到首页的全流程。

> 约定：后续每新增一个「对用户可见」的前端功能页面，都应在上述三个层级中至少覆盖前两个层级（单测 / 组件测试），关键路径覆盖第三层级（E2E）。

### 3.3 接口文档与前后端协作

- 后端通过 **SpringDoc OpenAPI（Swagger UI）** 暴露接口文档。
- 建议流程：
  1. 后端在 `OJPT-backend` 中先通过 controller + dto 定义接口，并更新 OpenAPI 描述。
  2. 前端新增或调整 `src/api/*.ts` 模块，与 OpenAPI 描述对齐。
  3. 在本 `PROJECT-PLAN.md` 中为该接口关联的功能项更新状态，并在测试小节增加计划/结果。

## 4. 测试结构与覆盖规划

本节从整体测试策略出发，定义：哪些模块需要哪些层级的测试，以便在后续任务中逐步填充。

### 4.1 测试结构总览（TS 专用）

本项目当前阶段的自动化测试 **全部基于 TypeScript 完成**，不再使用任何 Java/JUnit 形式的后端自测：

- **后端行为覆盖方式**
  - 通过前端工程中的 API 层单测（Vitest）与端到端测试（Playwright），以 HTTP 调用的方式覆盖后端接口与安全边界；
  - `OJPT-backend/src/test/java` 目录不再新增测试代码，如有历史文件仅作为参考或可逐步清理。
- **前端测试结构**
  - 具体的单元测试 / 组件测试 / E2E 测试结构与规范，见下文的「4.2 前端测试结构规划」与「4.3 测试状态跟踪表」。

### 4.2 前端测试结构规划

- **单元测试（TS）**
  - 覆盖 API 模块（`src/api/*`）、store（`src/stores/*`）、实用函数（`src/utils/*`）。
  - 使用 Vitest + @vue/test-utils，在 `OJPT-frontend/tests/unit` 下组织。

- **组件测试**
  - 对关键页面和复用组件（表单、表格、对话框等）进行渲染与交互验证。
  - 覆盖登录页、用户管理列表页、组织管理页等。

- **端到端测试（E2E，TS）**
  - 从登录 → 首页 → 某个典型业务流程的完整链路。
  - 使用 Playwright（`OJPT-frontend/tests/e2e`），接入 CI（或独立执行）。

## 7. 如何在后续新增/修改功能时更新本文件

为保证本文件始终有效，建议在新增或修改功能时按以下步骤操作：

- **步骤 1：确定功能归属模块**
  - 判断该功能属于：用户与权限 / 题库 / 评测 / 训练 / 分析 / 运维 中的哪一类。
  - 如不确定，可先挂到「临时功能/待归类」小节，稍后再归类。

- **步骤 2：在功能总表中增加/更新对应行**
  - 分配一个新的功能编号（例如 UA-008、BK-003）。
  - 填写名称、状态（通常先标记为「进行中」）、前端/后端/测试的当前情况。

- **步骤 3：在测试结构表中同步增加一行（如有必要）**
  - 如果该功能为「关键用户路径」（例如登录、题目提交、成绩查询），务必在测试表中增补一行，规划对应的测试层级。

- **步骤 4：如涉及调优点，在调优跟踪表中登记**
  - 比如：性能敏感的统计接口、安全敏感的授权操作、用户体验明显影响流程的页面。

- **步骤 5：在 PR 描述中引用本文件**
  - 在 PR 描述中增加一条：
    - 「已更新 `.cursor/doc/PROJECT-PLAN.md` 中对应功能状态与测试计划」。
