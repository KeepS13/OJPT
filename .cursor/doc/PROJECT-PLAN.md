# OJPT 项目计划

本文件作为当前仓库的文档基线，只记录与现有实现一致的规划。

## 角色基线

当前系统角色固定为：

- `USER`：普通用户
- `ADMIN`：管理员

约束：

- 不再以 `STUDENT`、`TEACHER`、`SCHOOL`、`SCHOOL_ADMIN` 作为系统角色推进功能
- 所有新文档、接口示例、页面说明都必须沿用双角色口径

## 当前已实现范围

### 普通用户侧

- 认证与登录态恢复
- 个人中心与安全设置
- 题库列表
- 题目详情 / 做题页

### 管理员侧

- 后台概览
- 用户管理
- 题目管理
- 标签管理
- 用户统计

## 当前 API 范围

### 公共或登录相关

- `/api/auth/**`
- `GET /api/problems`
- `GET /api/problems/{id}`
- `GET /api/problems/no/{problemNo}`

### 登录后普通用户

- `/api/users/**`

### 管理员

- `/api/admin/**`

## 近期文档约束

后续所有计划、README、API 说明遵循：

1. 只描述双角色系统。
2. 不保留“后续还会恢复多角色系统”的表述。
3. 历史多角色内容如有必要，只能标记为“历史设计已废弃”。
4. 示例响应中的 `roleType` 与 `roles` 必须符合当前实现。

## 文档检查清单

每次更新文档后至少检查以下关键词：

- `STUDENT`
- `TEACHER`
- `SCHOOL_ADMIN`
- `ROLE_STUDENT`
- `ROLE_TEACHER`
- `ROLE_SCHOOL`
- `多角色`

若命中结果仍指向当前系统说明，应继续清理；若仅为历史备注，必须明确写成“历史设计已废弃”。
